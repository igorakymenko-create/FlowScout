    How these settings work

    Every candidate action the crawler finds gets one of three risk tiers before it's ever clicked. This is what most fields below actually control.

    TierMeaningFollowed?
    safenavigation — links, opening menus, viewing pagesalways
    mutatingchanges state — add to cart, checkout, submit, purchase…only if allow_mutating is on
    destructivelogout, leaving the allowed domain(s), an excluded pagenever — no toggle overrides this

    Load saved config

    Prefills every field below from a JSON file in configs/. There's no limit on how many you can save — it's just files in a folder. Selecting — blank — resets the form to defaults. Save current settings as… writes the form to a new (or overwritten) file; the 🗑 button next to the dropdown deletes the selected one. All of this is also just editable by hand in configs/*.json if you prefer a text editor.

    Project name

    A label only — names the run's folder (runs/<project>-<timestamp>-<id>) and how it shows up in the list. No effect on crawl behavior.

    Start URL

    Where the crawl begins. Everything discovered has to be reachable by following links from here.

    Credentials

    Field-name → value pairs. When the crawler finds a form (e.g. a login page), it fills each input by matching the input's name/id/placeholder against these keys — case-insensitive, substring match. So a key of user-name also matches an input literally named username. Fields that don't match anything get a synthetic safe value instead (e.g. flowscout_test) — never left blank, never guessed from the page.

    Additional personas

    Crawls the same site again as a different logged-in user, one persona after another (not in parallel — two personas can corrupt each other's results through shared server-side state, e.g. one resetting cart contents mid-crawl while another is still using them), all written into one report. Flows are kept separate per persona even when they look identical otherwise — an admin-only page an admin can reach and a standard user can't never collapses into "the same flow" just because the destination matches. Each persona gets the same Max states / Max flows budget the crawl would give a single persona, not a shared pool that a later persona could get starved out of. Leave this empty to crawl as just the one persona defined in Credentials above (the default, and the only behavior before this existed).

    Max depth

    The longest chain of steps a single flow can take from the start page. Doesn't limit how many different flows get explored — only how deep any one of them goes.

    Max breadth / state

    How many candidate actions the crawler will try from one discovered page, out of everything it finds there. Extras beyond this are skipped ("breadth limit exceeded" in the report) — in practice the most common reason a real, visible button never gets clicked, especially when a site's header/footer repeats on every page and crowds out page-specific content ahead of it. Raise this if a run's report shows a lot of breadth-limit skips on pages you care about.

    Max states / Max flows

    Whole-run budgets: total distinct application states discovered, and total paths walked (unique + duplicate together), before the crawl stops.

    Allow mutating actions

    Off by default. When off, only safe actions are ever clicked. Turn this on when you're fine with the crawler actually performing add-to-cart/checkout/submit-style actions on the target — safe on a demo/QA site with fake data, risky on a site with a real payment processor wired up.

    Allowed domains

    The crawl never navigates outside these domains, regardless of the toggle above — anything pointing elsewhere is destructive and skipped, no exceptions.

    Exclude URL patterns

    Glob patterns (e.g. */privacy*) for pages you never want visited — legal pages, social links, anything not worth the crawl budget or not safe to touch. Same treatment as an external domain: always destructive, independent of the mutating toggle. Doesn't apply to in-page anchors (e.g. #faq) — only real page navigations have a path to match against.

    Embeddings provider

    Both Semantic dedup and Gap analysis need a text-embeddings API call to compare flows/test cases by meaning, not just exact text. Gemini was the only option originally; OpenAI and Voyage AI (Anthropic's own recommended embeddings partner — Anthropic has no embeddings model of its own) were added so an operator without a Gemini key isn't stuck. Gemini's integration is the one that's actually been exercised against real API calls, repeatedly, throughout this project's development. OpenAI's and Voyage's were built from each provider's documented API contract without a live key to test against — the ⚠ on their badge above means exactly that: verify with a real key before trusting the results, the same discipline every other feature here was held to. The 0.95 (dedup) and 0.74 (gap analysis) thresholds below were both measured empirically against Gemini's own similarity distribution; a different provider's embedding space won't necessarily cluster the same way at the same numbers.

    Semantic dedup — Enabled

    An extra pass after the crawl (needs a key for whichever provider you picked above) that merges flows reading as the same thing even when their exact steps differ. Off by default cost, and the run still fully works without it — just structural + state-convergence dedup only, both free and always on regardless of this setting.

    Semantic dedup — Similarity threshold

    How similar two flows' embeddings must be (cosine, 0–1) before they're called duplicates. Higher = stricter, fewer merges. The 0.95 default was set by testing real flow pairs against Gemini during development, not picked blind — lower thresholds were shown to merge flows that don't even end in the same application state. Not re-verified for OpenAI/Voyage — see Embeddings provider above.
